# muxscale client core

Shared by the iOS and Android apps through a thin FFI layer (UniFFI/JSI, M3).

Everything that must agree byte-for-byte with the daemon lives here rather than
in TypeScript: the grid model, the wire types, and the Noise transport. Two
reasons it is Rust and not JS — the grid delta path runs at up to 20 frames a
second and must stay off the JS thread entirely, and the protocol and crypto
need one implementation tested once rather than two hand-written ones that
drift.

## Cross-implementation conformance

`tests/cross_impl.rs` replays `fixtures/vt/cross-impl.json`, generated by the Go
daemon. It records, for a deliberately awkward script of terminal writes, the
snapshot and row delta the daemon would send and the screen the client should
end up with.

This is not ceremony. Two implementations of one wire format drift apart
silently, and the symptom is a phone rendering something the daemon never had —
close to impossible to diagnose from a bug report. The delta-only test is the
one that matters, because an error there compounds instead of being reset by the
next snapshot.

Regenerate the fixture after any change to the emulator or wire encoding:

```bash
cd go && MUXSCALE_UPDATE_FIXTURES=1 go test ./internal/vt -run CrossImpl
cd rust && cargo test
```

## Noise interop

`tests/noise_interop.rs` spawns the Go daemon's handshake peer and performs a
real Noise IK exchange against it, then compares the short authentication
string both sides derived independently.

This matters more than the usual cross-language test. Two implementations of a
security protocol that only ever test against themselves will agree with
themselves. A disagreement between them does not fail loudly -- it produces a
pairing that appears to work while the SAS check silently compares two
different phrases, so a legitimate pairing gets abandoned.

```bash
cd go && go build -o /tmp/noise-peer ./cmd/noise-peer
cd rust && cargo test
```

The interop tests skip if the peer is not built, so `cargo test` alone still
works.

## Build

```bash
cargo test           # unit + conformance
cargo clippy --all-targets
```

The release profile targets size over speed and aborts on panic: this runs on a
phone, and unwinding across the FFI boundary is undefined behaviour.
